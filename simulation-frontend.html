How HGB Becomes ONNX Usable Anywhere

Training (Offline, Once)
Load filtered_clean.parquet 836M → Temporal split 80/20 → StandardScaler fit on TRAIN only → HGB balanced 500 trees → Evaluate once → 0.9801 recall.
Conversion to ONNX (Portable)
Unified Pipeline (Scaler+HGB) → skl2onnx opset17 Input [None,32] → Sub/Div nodes → TreeEnsemble → Output. Save .onnx + SHA256 + metadata.json. Validate diff <1e-4, p99 0.5ms.
Is "usable anywhere" correct? Yes - Language-agnostic via ONNX Runtime Python/Go/Rust/Java/C++, needs Runtime + same 32 features same order seconds units.

04 • Architecture • FlowDetect 9 Layers

FlowDetect physical to visualization - production grade

FlowDetect 9 Layers: Physical Network TAP eth0 → Ingestion Scapy/AF_PACKET → Buffer Kafka raw-flows 3 partitions → Flow Assembly FlowKey 5-tuple → FlowState Redis TTL 30s → Feature Extraction 32 features → Inference ONNX Runtime batch 64 p99 0.5ms SHA256 → Decision Alert Router LOW/MED/HIGH/CRIT dedup 60s → Storage TimescaleDB hypertable → Visualization Grafana 5s. Fixed alignment with fc-row and ar-d centered.

Flow Assembly Layer - Critical Fix
v1 flaw: global dict + Lock → leak race single machine. v2 fix: Redis Streams TTL. FlowKey hash 5-tuple direction-invariant. Termination FIN/RST idle 30s max 300s 50k pkts. Heap TTL + 1s scanner not per-packet timer.
Inference Layer - Security Fix
v1 flaw: pickle.load → RCE. v2 fix: ONNX graph + SHA256 verified refuse tampered. Batching asyncio.Queue 1024 → collect 64 OR 10ms → single ONNX p99 0.5ms. Prometheus Counter Histogram Gauge.
