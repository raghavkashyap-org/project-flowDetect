flow-detect — Results & Honesty Audit

CICIDS2017 Friday · clean → split → train → validate → deploy

Downstream of DATASET-pre-training audit (16,137,183 rows / 83 cols)

Read this first. A 6-class model reaches 99.97% balanced accuracy. That number is largely an artifact: removing five per-tool TCP-stack columns costs 8.5 macro-F1 points and raises the false-positive rate 26×. The deployed model uses the 27-feature behavioural set.
Deployed and verified. HistGradientBoosting on all 8,197,703 training rows, gate at τ = 0.921056, exported to ONNX. On the full 1,755,657-row test split: recall 97.93%, benign FPR 0.307%, 24.18% precision at a 1-in-1,000 attack prior, cost 5.14 per 1,000 flows against a do-nothing baseline of 100.

The ONNX export reproduces the native model exactly at the operating threshold — 0 gate flips on 400,000 rows — and a 14-check end-to-end audit (verify_deploy.py) reproduces every metric in the model card with zero delta.

5. Deployed operating point

An IDS decision is two steps: gate (alert at all? score = 1 − P(Benign) ≥ τ) then label (which family?). Every candidate threshold — one per validation row, 1,769,164 of them — is evaluated exactly by sort + cumulative sum and written to threshold_sweep.npz. The threshold is chosen on validation and reported on the untouched test split.

The 0.19 max diff is float32 rounding, not a defect — but the margin is not free. ONNX runs the trees in float32 (~7 significant digits). CICIDS features such as Flow Byts/s and Bwd IAT Tot reach 1e9–1e10, where adjacent float32 values are thousands apart. Reproduced deliberately: small-valued fixtures give 1.9e-07; CICIDS-magnitude fixtures give 0.94.

Decisions on the checked rows are unchanged. But a synthetic draw from the same recipe produced 7 gate flips in 30,000 rows, so this is a tail risk, not a guarantee. Mitigation: in the Alert Router, re-score any flow whose score lands within ~0.01 of τ through the native joblib model.

End-to-end verification

verify_deploy.py re-implements inference from scratch, reading feature order, class order and τ from onnx_card.json rather than from the Python model, then scores the full test split and compares against model_card.json.

All 14 checks pass with zero delta on TP, FP, FN, FPR, recall, precision, cost and every per-family count, across 1,755,657 rows.

Confirmed the check can fail: permuting the feature order, setting the wrong benign column index, and reverting τ to the old 0.92419 each produce FAIL and exit code 1. A permuted feature order otherwise yields confident garbage with no error anywhere.

7. What to report

Primary result: 4-family behavioural IDS on 27 template-free features, trained on 8,197,703 flows. At the deployed operating point (τ = 0.921056, prior 1-in-1,000, miss = 100× false alarm): 97.93% attack recall, 0.307% benign FPR, 24.18% precision, 5.14 cost per 1,000 flows against a do-nothing baseline of 100.

State explicitly: 6-class accuracy is 99.97%, but 8.5 macro-F1 points of that come from five per-tool TCP-stack columns. The 6-class figure is the fingerprint-dependent upper bound, not detection performance.

State the weakness: 94.0% of misses are Flood, tracing to HOIC-vs-Hulk separability of 0.9043 once tool fingerprints are removed.

8. Limitations

  1. No cross-session evaluation is possible. Every attack class occurs on exactly one capture day (HOIC d21, LOIC-HTTP d20, Hulk d16, Bot d2, SSH d14), so leave-one-day-out removes the class from training entirely. CICIDS2017 cannot test generalisation to an unseen capture.
  2. Random split shares bursts. Attacks are single-hour bursts; a 70/15/15 content split still puts near-identical rows on both sides. Even 0.9793 recall is an optimistic reading of field performance.
  3. Flood dominates the residual error — 3,389 of 3,604 misses (94.03%).
  4. Precision is prior-dependent and low. 24.18% at 1-in-1,000 means roughly 3 false alarms per true detection. This is inherent to the prior, not a defect — but it must be stated, and the dataset's own 9.90% balance must never be quoted instead.
  5. The ONNX export is not bit-exact. 0 gate flips on 400,000 rows, but float32 rounding on features up to 1e10 makes it a tail risk. Guard the gate.
  6. More data does not help. 4× the training rows bought 1.71%. The ceiling is the data, not the learner or the sample size.
  7. LOIC-UDP anomaly unresolved (from the audit): 1,730 flows all on port 80 with ACK ≈ 0.96 — likely mislabeled TCP. The class was dropped, so it does not affect results, but it remains a data-integrity flag.
